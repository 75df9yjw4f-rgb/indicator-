# CVD Structural Divergence Scalper [1m] — BTCUSDT

Pine Script **v6** `strategy()` (индикатор + бэктест в одном скрипте).

Файл: **`CVD_Structural_Divergence_Scalper.pine`** — вставить целиком в Pine Editor →
`Add to chart`. Скрипт открывается **отдельной панелью** (там CVD), а EMA, структура
цены, линии дивергенций, сигналы и уровни Entry/SL/TP рисуются на **основном графике**
через `force_overlay = true`.

Концепция не изменена:

```
PRICE STRUCTURE  <->  CVD STRUCTURE
        -> 4 типа структурного несоответствия
        -> ожидание EMA (окно N баров)
        -> EMA cross
        -> LONG / SHORT
        -> SL / TP
        -> Strategy Tester
```

---

## 0. Техническое ограничение — читать первым

**Pine Script не может прочитать числовое значение встроенного индикатора TradingView
«Cumulative Volume Delta».** В Pine вообще нет API, который возвращает вывод другого
скрипта. Поэтому «взять готовый CVD из TradingView» технически невозможно, и скрипт
этого не имитирует.

Что сделано вместо этого: CVD **строится внутри стратегии из того же самого исходного
материала**, который использует встроенный индикатор — из свечей младшего таймфрейма
(intrabar), через `request.security_lower_tf()`. Это максимально близкий технически
корректный вариант, без будущих данных и без `lookahead`.

Подробности и ограничения такого CVD — в разделе 15.

## 1. Как рассчитывается CVD

Блок `CVD ENGINE` в коде.

1. `request.security_lower_tf(syminfo.tickerid, safeLtf, [open, close, volume])`
   возвращает **массив** свечей младшего ТФ, принадлежащих **текущему** бару графика.
   В нём физически не может быть будущих данных.
2. Каждая intrabar-свеча классифицируется стандартным правилом (тем же, что использует
   Volume Delta в TradingView):
   * `close > open` → весь объём свечи — **покупки**, `delta = +volume`;
   * `close < open` → весь объём свечи — **продажи**, `delta = -volume`;
   * `close == open` → **tick rule**: сравнение с предыдущим intrabar-close; если и там
     равенство — переносится последнее известное направление (`lastDir`).
3. `barDelta` = сумма intrabar-дельт → это **свечная дельта** (не накопленная).
4. `cvd = cvd[1] + barDelta` → это **накопленная дельта, CVD**.
5. Во время суммирования отслеживается текущее накопленное значение, поэтому
   получается полноценная **свеча CVD**: `cvdOpen / cvdHigh / cvdLow / cvdClose`.
   Структура CVD читается именно по этим значениям, а не по сглаженной линии.

В скрипте три сущности строго разделены:

| Сущность | Переменные | Что это |
|---|---|---|
| Цена | `open/high/low/close` | обычный график |
| Свечная дельта | `barDelta` | buy − sell **за один бар** |
| CVD | `cvdOpen/cvdHigh/cvdLow/cvdClose` | накопленная дельта |

`barDelta` и число использованных intrabar-свечей выведены в Data Window — можно
проверить качество данных на любом баре.

**Fallback.** Если intrabar-данные недоступны (тариф без секундных ТФ, глубина истории
за лимитом запроса, символ без нужных данных) или выбран режим
`Bar-based approximation`, дельта считается по форме самой свечи графика:

```
buy  = volume * (close - low ) / (high - low)
sell = volume * (high - close) / (high - low)
barDelta = buy - sell
```

Это приближение, и в таблице статистики первая строка честно показывает, какой режим
реально работает: `intrabar 15S` или `bar-based`.

**Reset.** `CVD reset` = `None / Daily session / Weekly`. При сбросе увеличивается
счётчик `cvdEpoch`, и пивоты из разных «эпох» **никогда не сравниваются между собой** —
разрыв ряда не создаёт ложных дивергенций.

## 2. Как определяются Price pivots

* `ta.pivothigh(pSrcHi, Price Pivot Left, Price Pivot Right)` и
  `ta.pivotlow(pSrcLo, ...)`.
* Источник переключается: `High / Low` (по умолчанию) или `Close`.
* Пивот **подтверждается только после закрытия `Right` баров справа**. На баре
  подтверждения сам пивот находится на `bar_index - Price Pivot Right`.
* Подтверждённый пивот кладётся в кольцевой буфер `phArr` (максимумы) или `plArr`
  (минимумы) как объект `Piv { bar, confBar, val, epoch, tag, mVal, mBar }`.
* `tag` — структурная классификация относительно **предыдущего** пивота того же типа:
  `HH / LH` для максимумов, `LL / HL` для минимумов (первый пивот получает `H` / `L`).
  Метки рисуются на основном графике.

Значения по умолчанию для 1m: `Left = 5`, `Right = 3`.

---

## 3. Как определяются CVD pivots

Полностью независимо от цены, своими настройками `CVD Pivot Left / Right`:

* источник — `cvdHigh` / `cvdLow` (по умолчанию) или `cvdClose`, переключатель
  `CVD pivots are taken from`;
* та же функция `ta.pivothigh/ta.pivotlow`, то же правило подтверждения;
* пивоты идут в `chArr` / `clArr` и точно так же получают `HH/HL/LH/LL`;
* метки рисуются **на панели CVD**, поэтому расхождение структур видно глазами:
  на цене `HH`, а на CVD в том же месте `LH`.

Цена и CVD подтверждаются **независимо**, и CVD-пивот может подтвердиться позже
ценового — этот случай обработан отдельно (см. раздел 5).

## 4. Как работает `Historical Pivots To Scan`

Это ядро стратегии. Сравнения «только с предыдущим максимумом» здесь нет.

Когда подтверждается новый ценовой максимум `H21`, функция `scanPairs()` берёт его как
«якорь» и идёт назад по массиву:

```
H21 vs H20
H21 vs H19
H21 vs H18
...
до H(21 - Historical Pivots To Scan)
```

По умолчанию `20`, можно поставить 5 / 10 / 30 / 50 и т. д. Для минимумов — зеркально
(`L21` против `L20 … L1`).

Правила корректности, заложенные в цикл:

* **High сравнивается только с High, Low только с Low** — массивы физически разные;
* сохраняется временная последовательность: «новый» пивот всегда правее «старого»
  (цикл идёт от `anchorIdx - 1` вниз);
* у обоих концов пары должен быть найден **свой** CVD-пивот (`mBar != na`);
* оба конца должны принадлежать одной CVD-эпохе;
* бессмысленные комбинации не создаются: пара считается дивергенцией только если
  направление цены и направление CVD **противоположны**.

Один новый пивот может дать несколько валидных дивергенций с разными историческими
пивотами — это поддержано, но ограничено настройкой
`Max Divergences Per New Pivot` (по умолчанию 3), а общее число отображаемых
дивергенций — `Max Divergences Displayed` (по умолчанию 12), чтобы график не
превращался в хаос.

Защита от дублей: пара `(бар нового пивота, бар старого пивота)` записывается в
dedupe-буфер, повторно та же пара не создаётся никогда.

## 5. Как происходит сопоставление Price ↔ CVD

Требования «пивот цены и пивот CVD на одной свече» **нет**.

* Настройка `Pivot Matching Window (bars)`, по умолчанию `6` для 1m.
* Функция `findMatch()` ищет **ближайший** CVD-пивот **того же типа** в пределах
  `± matchWin` баров от ценового пивота. High ищется только среди CVD-High, Low —
  только среди CVD-Low.
* Найденное сохраняется прямо в объекте ценового пивота: `mVal` (значение CVD) и
  `mBar` (бар CVD-пивота). Благодаря этому дальнейшее сканирование пар не делает
  вложенных поисков — O(N) вместо O(N²).
* **Поздняя привязка.** Если CVD-пивот подтвердился позже ценового, то в момент его
  подтверждения скрипт проходит по последним ценовым пивотам, находит те, что попадают
  в окно, проставляет им `mVal/mBar` (или заменяет на более близкий) и **заново**
  запускает сканирование пар для этого пивота и нескольких следующих (`scanFrom`).
  Дубликаты отсекает dedupe-буфер.

Значение CVD для конца пары — это всегда значение **CVD-пивота**, а не CVD произвольной
свечи.

## 6. Как находятся все 4 вида дивергенции

Для пары максимумов (`isHigh = true`) и пары минимумов (`isHigh = false`) сравниваются
цена и соответствующий CVD:

| Тип | Цена | CVD | Структурно |
|---|---|---|---|
| **Type 1** | HH (`new > old`) | LH (`new < old`) | bearish |
| **Type 2** | LL (`new < old`) | HL (`new > old`) | bullish |
| **Type 3** | HL (`new > old`) | LL (`new < old`) | bullish |
| **Type 4** | LH (`new < old`) | HH (`new > old`) | bearish |

Каждый тип включается/выключается отдельным чекбоксом. **В интерфейсе нет разделов
«бычьи» и «медвежьи» — есть ровно четыре типа**, как и требовалось. Внутренний флаг
`bull` существует только для работы фильтра направления.

Дополнительные (по умолчанию выключенные) шумовые фильтры:
`Min Price Pivot Difference (%)` и `Min CVD Pivot Difference (%)` — второй нормируется
на диапазон CVD за последние 200 баров.

Для каждой найденной дивергенции скрипт:

* рисует линию между двумя **ценовыми** пивотами на основном графике;
* рисует линию между двумя соответствующими **CVD**-пивотами на панели CVD;
* ставит подпись типа (`T1 Price HH / CVD LH` и т. д.) у ценового пивота и короткую
  метку (`LH`, `HL`, …) у CVD-пивота;
* сохраняет событие в массив `divArr` вместе с **баром обнаружения** (`bar_index` в
  момент, когда информация реально стала доступна) — именно он потом используется для
  окна ожидания EMA.

## 7. Как работает Direction Filter

Настройка `Divergence Direction Filter`:

* **Strict Direction** (по умолчанию)
  * Type 2 и Type 3 (структурно bullish) → разрешают **только LONG**;
  * Type 1 и Type 4 (структурно bearish) → разрешают **только SHORT**.
  * Есть bullish-дивергенция, а EMA пересекается вниз → SHORT **не открывается**.
  * Есть bearish-дивергенция, а EMA пересекается вверх → LONG **не открывается**.
* **Any Divergence**
  * любая живая дивергенция «взводит» систему в обе стороны, направление сделки
    определяет исключительно пересечение EMA.

Настройка реально работает и в визуализации, и в бэктесте: функция `divPermits()`
вызывается отдельно для лонга и для шорта.

`Divergence Selection Mode`:

* **Latest Valid Divergence** (по умолчанию) — при пересечении EMA опрашивается только
  **самая свежая подходящая по возрасту** дивергенция; если она смотрит в другую
  сторону, сделки нет;
* **Any Valid Divergence** — опрашиваются все живые дивергенции, достаточно одной
  подходящей.

В обоих режимах **все** найденные дивергенции всё равно рисуются на графике.

## 8. Как работает окно подтверждения EMA (15 баров)

Дивергенция — **не вход**. Она только запускает окно ожидания.

```
Divergence (бар D)
   ↓ 1, 2, 3 … 15 свечей   (Max Bars After Divergence = 15 по умолчанию)
EMA cross
   ↓
SIGNAL
```

* Возраст считается как `bar_index - d.bar`, где `d.bar` — бар обнаружения.
* Допустимый возраст: от `1` до `Max Bars After Divergence`. Переключатель
  `Allow EMA cross on the divergence bar itself` (по умолчанию выкл.) разрешает
  возраст `0`.
* Пересечение на 16-м баре — дивергенция уже помечена `alive = false`, сигнала нет.
* Несколько дивергенций внутри окна хранятся как **отдельные события** и не затирают
  друг друга (`divArr`, до 60 последних).
* `Consume divergences after a signal` (по умолчанию вкл.) гасит живые дивергенции
  после сигнала, чтобы одна и та же дивергенция не стреляла многократно.

EMA **ровно одна**: `EMA Length` (по умолчанию 20), источник настраивается, рисуется на
основном графике. `EMA Cross Confirmation`:

* **On Bar Close** (по умолчанию) — кросс должен «дожить» до закрытия свечи
  (`barstate.isconfirmed`) → **не перерисовывается**;
* **Intrabar / realtime** — кросс принимается сразу внутри живой свечи; в реальном
  времени он может «отмениться» до закрытия. На исторических барах оба режима
  идентичны, поэтому сам бэктест остаётся non-repainting в любом случае.

---

## 9. Как формируется LONG

1. Есть подтверждённая дивергенция, которой не больше `Max Bars After Divergence` баров.
2. В режиме Strict Direction её структура должна быть bullish (Type 2 или Type 3);
   в режиме Any Divergence годится любая.
3. На закрытии бара `close` пересекает EMA **снизу вверх** (`ta.crossover`).
4. Бар внутри диапазона бэктеста.
5. → на графике печатается метка **LONG**, счётчик `Signals Generated` увеличивается.
6. Если позиции нет — отправляется `strategy.entry("L", strategy.long)`.

## 10. Как формируется SHORT

Зеркально: bearish-дивергенция (Type 1 или Type 4) в Strict Direction либо любая живая
в Any Divergence + `ta.crossunder(close, EMA)` → метка **SHORT** и, если позиции нет,
`strategy.entry("S", strategy.short)`.

## 11. Как работает «одна открытая позиция»

* В заголовке стратегии `pyramiding = 0`.
* Плюс явная проверка: вход выполняется только если `strategy.position_size == 0`.
* Если позиция уже открыта, встречный сигнал:
  * **рисуется** на графике (метка LONG/SHORT);
  * **считается** в `Signals Generated`;
  * попадает в отдельную строку таблицы `Signals blocked (in pos.)`;
  * **не открывает** новую сделку и не считается сделкой.
* После закрытия позиции следующий валидный сигнал снова может открыть сделку.
* Исключение только одно и оно опционально: `Reverse on opposite signal` (по умолчанию
  выкл.) — при включении встречный сигнал закрывает и разворачивает позицию.
* При `Take Profit Mode = Opposite Signal` встречный сигнал **закрывает** текущую
  сделку, но (при выключенном реверсе) новую не открывает — ровно как в ТЗ.

Разница между `Signals Generated` и `Trades Actually Opened` в таблице показывает,
сколько сигналов было пропущено из-за занятой позиции.

## 12. Как работают SL / TP

Уровни считаются **в момент отправки ордера**, от цены, по которой ордер реально
исполнится (`close` текущего бара при `process_orders_on_close = true`), и защитные
ордера выставляются **на том же баре** — сделка не остаётся без защиты ни на один бар.

### Stop Loss Mode

| Режим | Как считается |
|---|---|
| **Swing / Pivot SL** (по умолчанию) | Для LONG — проход назад по подтверждённым структурным **минимумам** (`plArr`, глубина `Swing SL: pivots to look back`) до первого, который реально **ниже** цены входа, минус буфер в тиках. Для SHORT — зеркально по максимумам. Если подходящего свинга нет — автоматический откат на ATR, «пустого» стопа не бывает. |
| **Fixed Percentage SL** | `entry ± entry * slPct / 100` |
| **ATR-based SL** | `entry ± ATR(atrLen) * atrMultSL` |
| **Fixed Points/Ticks SL** | `entry ± slTicks * syminfo.mintick` (для BTCUSDT перп тик = 0.1, значит 500 тиков = 50 USD) |

Дополнительно: `Min SL distance (%)` (защита от нулевого стопа, работает во всех
режимах) и `Max SL distance (%)` (ограничитель только для свингового стопа).

### Take Profit Mode

| Режим | Как считается |
|---|---|
| **Risk / Reward** (по умолчанию 1:1.5) | `entry ± risk * rrRatio`, где `risk = |entry − SL|`. Ставьте 1, 1.5, 2, 3 … |
| **Fixed Percentage** | `entry ± entry * tpPct / 100` |
| **ATR-based** | `entry ± ATR(atrLen) * atrMultTP` |
| **Fixed Points/Ticks** | `entry ± tpTicks * syminfo.mintick` |
| **Opposite Signal** | лимитного тейка нет, позиция закрывается встречным сигналом (стоп при этом работает) |

### Same Bar TP/SL Resolution

Что считать первым, если одна свеча накрыла и стоп, и тейк:

* **Conservative (SL first)** — по умолчанию. Выставляется OCA-пара `stop + limit`
  одним `strategy.exit()`. Брокерский эмулятор Pine не знает внутрисвечной
  последовательности и разрешает неоднозначность по худшему сценарию, то есть по стопу.
  Это и есть консервативный (реалистичный) бэктест.
* **Optimistic (TP first)** — армируется только тейк, поэтому свеча, накрывшая оба
  уровня, исполняется по тейку. Свеча, пробившая стоп и не дошедшая до тейка,
  закрывается рыночно **по закрытию этой свечи** (честная оговорка: это единственное
  место, где цена выхода не равна точному уровню стопа — иначе пришлось бы отдать
  разрешение коллизии эмулятору и режим перестал бы работать).

Отдельная строка таблицы `Same-bar TP+SL collisions` показывает, сколько раз ситуация
вообще возникала — можно оценить, насколько выбор режима влияет на результат.

### Entry Mode

* **Signal Candle Close** (по умолчанию) — ордер отправляется на сигнальном баре и,
  так как скрипт объявлен с `process_orders_on_close = true`, исполняется по **close
  этого бара**. Никакого lookahead: close известен в момент закрытия бара.
* **Next Candle Open** — ордер откладывается на один бар.
  **Честное ограничение Pine:** `process_orders_on_close` — константа времени
  компиляции, её нельзя вывести в настройки. С дефолтным заголовком отложенный ордер
  исполнится по close следующего бара. Для точного исполнения по **open** следующего
  бара нужно в заголовке `strategy()` поменять `process_orders_on_close = true` на
  `false` (строка помечена комментарием `// <- set to FALSE ...`). Тогда режим
  `Next Candle Open` становится точным, а `Signal Candle Close` — приблизительным.
  Оба режима одновременно точными в Pine быть не могут.

### Размер позиции

`Position Size Mode`: `Strategy Properties` (по умолчанию — берётся из вкладки
Properties), `Contracts`, `% of Equity`, `Cash (quote currency)`.

## 13. Как работает бэктест

Это полноценная `strategy()`, её тестирует штатный **Strategy Tester**.

* `Limit backtest to a date range` + `Backtest Start Date` / `Backtest End Date` —
  вне диапазона входы не выполняются; `Close open position at the end of the range`
  закрывает позицию на границе.
* **Initial Capital / Commission / Slippage.** Pine требует, чтобы эти параметры были
  константами в заголовке `strategy()`, поэтому их «рабочие» значения живут во вкладке
  **Strategy Tester → Properties** (в заголовке заданы разумные дефолты: капитал 10 000,
  комиссия 0.04 % — тейкер BTCUSDT перп, проскальзывание 1 тик). В таблице показаны:
  * `Initial Capital` — реальное значение (`strategy.initial_capital`);
  * `Commission (charged)` — **фактически списанная** комиссия, просуммированная по
    закрытым сделкам (`strategy.closedtrades.commission()`), плюс справочный процент из
    настроек;
  * `Slippage (reference)` — справочное значение из настроек (в Pine нет геттера
    реального проскальзывания), держите его синхронным с Properties.

### Таблица статистики

`Divergences found`, `Signals Generated` (с разбивкой L/S), `Trades Actually Opened`,
`Signals blocked (in pos.)`, `Total Trades`, `Winning Trades`, `Losing Trades`,
`Win Rate`, `Profit Factor`, `Net Profit`, `Max Drawdown`, `Average P/L`,
`Long Win Rate`, `Short Win Rate`, `Average R:R (realised)`, `Commission (charged)`,
`Slippage`, `Initial Capital`, `Same-bar TP+SL collisions`.

Статистики серий побед/поражений **нет** — как и просили.

`Average R:R (realised)` — средний реализованный R-мультипликатор: для каждой сделки
риск запоминается при входе (`|entry − SL|`), после закрытия считается
`(exit − entry)/risk` (для шорта — зеркально). Закрытые сделки обрабатываются
**инкрементально**, только новые, поэтому таблица не нагружает 1m-график.

## 14. Как предотвращён repaint / lookahead

В коде эти места помечены комментариями.

1. **Нигде нет `lookahead_on`.** Единственный внешний запрос —
   `request.security_lower_tf()`, который по своей природе отдаёт только intrabar-данные
   **текущего** бара.
2. **Пивот попадает в работу только после подтверждения.** `ta.pivothigh/ta.pivotlow`
   возвращают значение лишь после закрытия `Right` баров справа.
3. **Сигнал не переносится в прошлое.** Дивергенция получает `bar` = `bar_index` того
   бара, **на котором стали известны оба пивота и обе привязки** (включая случай, когда
   CVD-пивот подтвердился позже). Окно ожидания EMA отсчитывается от этого бара.
   Линия дивергенции при этом визуально протянута назад к реальным пивотам — это
   разрешено и не влияет на торговлю.
4. **Кросс EMA подтверждается на закрытии** (`barstate.isconfirmed`) в основном режиме.
5. **Вход по известной цене.** `Signal Candle Close` использует close бара, который уже
   закрылся.
6. **Защитные ордера выставляются на баре входа**, а не «задним числом»: стоп/тейк
   физически не могут исполниться на самом баре входа, так как для лонга стоп ниже, а
   тейк выше close этого бара.
7. **Никаких будущих значений** (`[-1]`, `security` со старшего ТФ и т. п.) в расчёте
   сигналов нет.

Режим `Intrabar / realtime` для кросса EMA — единственное место, которое в реальном
времени может «мигать»; это явно указано в тултипе, по умолчанию он выключен, и на
историю он не влияет.

## 15. Какие ограничения есть у CVD в TradingView

1. **Значение встроенного индикатора CVD недоступно из Pine** — см. раздел 0.
2. **Биржевой объём ≠ агрегированный.** CVD считается по объёму того символа, на
   котором открыт график (например `BINANCE:BTCUSDT.P`), а не по всему рынку.
3. **Нет реальных данных по агрессору.** TradingView не отдаёт в Pine поток сделок с
   флагом buyer/seller-initiated. Любой CVD в Pine (и встроенный тоже) реконструирует
   направление по свечам младшего ТФ — это приближение, а не биржевой tape.
4. **Лимит intrabar-запроса.** `request.security_lower_tf()` может вернуть ограниченное
   суммарное число младших баров (20 000 – 200 000 в зависимости от тарифа). Чем мельче
   `Intrabar timeframe`, тем короче доступная история: на 1m-графике `15S` даёт 4
   intrabar-свечи на бар (≈ в 4 раза меньше истории, чем без них), `1S` — 60.
   За пределами лимита массив приходит пустым и автоматически включается bar-based
   аппроксимация; первая строка таблицы это показывает.
5. **Секундные таймфреймы требуют платного тарифа.** На бесплатном плане `15S` вернёт
   пусто → сработает fallback.
6. **Точность формы CVD-свечи.** `cvdHigh`/`cvdLow` строятся как максимум/минимум
   накопленного пути внутри бара по порядку intrabar-свечей — это максимум доступной
   точности, но не тиковый путь.
7. **Сброс CVD.** Абсолютный уровень непрерывного CVD зависит от точки старта расчёта,
   поэтому сравнивать имеет смысл **структуру**, а не абсолютное значение — что скрипт
   и делает.
8. **Реалтайм.** На незакрытом баре CVD достраивается по мере поступления intrabar-
   свечей; подтверждённая структура при этом не меняется.

## Быстрый старт

1. BTCUSDT (лучше перп, например `BINANCE:BTCUSDT.P`), таймфрейм **1m**.
2. Вставить `CVD_Structural_Divergence_Scalper.pine` в Pine Editor → `Add to chart`.
3. Проверить первую строку таблицы: если там `bar-based`, значит intrabar-данные
   недоступны — поменяйте `Intrabar timeframe` (например на `30S`) или примите
   аппроксимацию.
4. Strategy Tester → Properties: выставить капитал, комиссию и проскальзывание, затем
   продублировать комиссию/слиппедж в группу `9 - Backtest` (они только для таблицы).
5. Настроить период в `Backtest Start/End Date`.

Ориентиры по параметрам для 1m: `Price/CVD Pivot Left = 5`, `Right = 3`,
`Historical Pivots To Scan = 20`, `Pivot Matching Window = 6`,
`Max Bars After Divergence = 15`, `EMA Length = 20`.
Больше `Right` → меньше шума, но позднее подтверждение. Больше
`Historical Pivots To Scan` → больше дивергенций (и больше сигналов).

> Ордерные метки самой стратегии TradingView рисует в панели скрипта (скрипт объявлен
> `overlay = false`, чтобы существовала панель CVD). Отключить их можно в
> Settings → Style → Trades on chart. Все торговые объекты стратегии — EMA, структура,
> линии дивергенций, LONG/SHORT, Entry/SL/TP — выведены на основной график отдельно.
